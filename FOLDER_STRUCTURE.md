## Detailed Component Descriptions

### Base Components

#### `src/components/base/Header.astro`
The site header containing profile information and social links.
- **Responsibilities**: Display name, title, location, social buttons
- **Props**: None (static content) or configurable via frontmatter
- **Styling**: Uses existing Bulma classes + custom profile styles

#### `src/components/base/Footer.astro`
The site footer with social icons and copyright.
- **Responsibilities**: Social icon links, attribution
- **Props**: None
- **Styling**: Existing footer styles

### Section Components

#### `src/components/sections/TLDRSection.astro`
The gradient welcome banner at the top.
- **Responsibilities**: Display welcome message
- **Props**:
  - `title`: string (default: "Welcome")
  - `content`: string
- **Styling**: Purple gradient background, custom animation

#### `src/components/sections/ProfileSection.astro`
Profile picture, name, and social buttons.
- **Responsibilities**: Display profile image, name, title, location, social links
- **Props**:
  - `name`: string
  - `title`: string
  - `location`: string
  - `profileImage`: string
  - `cvUrl`: string
  - `socialLinks`: object
- **Styling**: Circular profile picture with zoom effect

#### `src/components/sections/CatsSection.astro`
Showcase of Missy and Boba with hover effects.
- **Responsibilities**: Display cat pictures with names revealed on hover
- **Props**:
  - `cats`: Array<{name: string, image: string}>
  - `description`: string
- **Styling**: Circular cat pictures, hover name reveal, description text

### Project Components

#### `src/components/projects/ProjectCard.astro`
Individual expandable research project card.
- **Responsibilities**: Display project info, handle expansion, show badges
- **Props**:
  ```typescript
  interface Props {
    title: string;
    conference: string;
    authors: Array<{
      name: string;
      url?: string;
      isMe?: boolean;
    }>;
    tldr: string;
    overview: string;
    details?: string;
    colorTheme: 'blue' | 'orange' | 'green' | 'purple' | 'cream' | 'lightblue';
    badges: {
      website?: string;
      arxiv?: string;
      github?: string;
    };
    catImages?: {
      left: string;
      right: string;
    };
  }
  ```
- **Styling**: Color-themed borders, expandable content, badge positioning
- **Behavior**: Click to expand/collapse (excluding badges)

#### `src/components/projects/ProjectBadge.astro`
Individual badge for conference/website/arxiv/github.
- **Responsibilities**: Display styled badge with link
- **Props**:
  - `type`: 'conference' | 'website' | 'arxiv' | 'github'
  - `text`: string
  - `url?`: string (optional for conference)
- **Styling**: Gradient backgrounds, hover effects
- **Behavior**: Prevent click propagation to parent

### Blog Components

#### `src/components/blog/BlogPostCard.astro`
Blog post preview card for listing page.
- **Responsibilities**: Display post title, date, description, tags
- **Props**:
  ```typescript
  interface Props {
    title: string;
    slug: string;
    description: string;
    date: Date;
    tags: string[];
  }
  ```
- **Styling**: Card with hover effect, similar to project cards

#### `src/components/blog/BlogPostHeader.astro`
Header for individual blog posts.
- **Responsibilities**: Display title, date, tags, reading time
- **Props**:
  - `title`: string
  - `date`: Date
  - `tags`: string[]
  - `readingTime?`: string
- **Styling**: Similar to project headers, consistent typography

## Layouts

### `src/layouts/BaseLayout.astro`
Base HTML structure for all pages.
- **Includes**: `<html>`, `<head>`, `<body>` tags
- **Features**:
  - Meta tags (charset, viewport, description, keywords)
  - Title management
  - Font imports (Google Fonts)
  - CSS imports (global, Bulma, component styles)
  - Script imports (FontAwesome, custom scripts)
  - Favicon
- **Slots**: Main content slot

### `src/layouts/MainLayout.astro`
Layout for homepage.
- **Extends**: BaseLayout
- **Includes**: Header, Footer
- **Features**: Main page structure
- **Slots**: Content area

### `src/layouts/BlogPostLayout.astro`
Layout for individual blog posts.
- **Extends**: BaseLayout
- **Includes**: Header, Footer, BlogPostHeader
- **Features**:
  - Article wrapper with proper semantic HTML
  - Prose styling for markdown
  - Navigation to blog index
  - Optional table of contents
- **Slots**: Content (markdown) slot

## Pages

### `src/pages/index.astro`
Main homepage.
- **Uses**: MainLayout
- **Components**: All section components
- **Behavior**: Expandable sections, smooth scrolling

### `src/pages/blog/index.astro`
Blog listing page.
- **Uses**: MainLayout
- **Features**:
  - Fetch all blog posts from content collection
  - Sort by date (newest first)
  - Display using BlogPostCard components
  - Optional tag filtering
- **Behavior**: Standard navigation, no special interactions

### `src/pages/blog/[slug].astro`
Dynamic blog post page.
- **Uses**: BlogPostLayout
- **Features**:
  - Dynamic routing based on slug
  - Fetch post from content collection
  - Render markdown content
  - Display tags, date, etc.
  - Links to other posts (prev/next)
- **Behavior**: Standard article reading experience

## Scripts

### `src/scripts/expandable.ts`
Handles expandable section functionality.
```typescript
export function initExpandableSections() {
  const expandableSections = document.querySelectorAll('.expandable-section');

  expandableSections.forEach(section => {
    section.addEventListener('click', function(event) {
      // Prevent expansion if badge was clicked
      if (event.target.closest('.badge')) {
        return;
      }

      this.classList.toggle('expanded');
    });
  });
}

// Auto-initialize on DOMContentLoaded
if (typeof document !== 'undefined') {
  document.addEventListener('DOMContentLoaded', initExpandableSections);
}
```

## Notes on Organization

### Why This Structure?

1. **Component-Based**: Clear separation of concerns, reusable components
2. **Feature-Based Folders**: Related components grouped together (base/, sections/, projects/, blog/)
3. **Style Organization**: Matches component structure for easy discovery
4. **Content Collections**: Type-safe blog posts with validation
5. **Public Assets**: Static files served directly without processing
6. **Clear Layouts**: Inheritance pattern for consistent structure

### Naming Conventions

- **Components**: PascalCase with `.astro` extension (e.g., `ProjectCard.astro`)
- **Styles**: kebab-case with `.css` extension (e.g., `project-card.css`)
- **Scripts**: camelCase with `.ts` extension (e.g., `expandable.ts`)
- **Content**: kebab-case with `.md` extension (e.g., `my-blog-post.md`)
- **Images**: lowercase with underscores (e.g., `missy_pic1.jpg`)

### File Size Guidelines

- **Components**: < 200 lines (break into smaller components if larger)
- **Style files**: < 300 lines (break into multiple files if larger)
- **Scripts**: < 150 lines (break into modules if larger)

### Import Conventions

```typescript
// Astro components
import Layout from '@/layouts/BaseLayout.astro';
import ProjectCard from '@/components/projects/ProjectCard.astro';

// Styles
import '@/styles/global.css';
import '@/styles/components/projects.css';

// Scripts
import { initExpandableSections } from '@/scripts/expandable';

// Content collections
import { getCollection } from 'astro:content';
```

(Note: The `@` alias can be configured in `tsconfig.json` to point to `src/`)

## Maintenance Guidelines

### Adding a New Research Project

1. Edit `src/pages/index.astro`
2. Add a new `<ProjectCard>` component with appropriate props
3. Add cat decoration images to `public/images/` if needed
4. No other changes needed!

### Adding a Blog Post

1. Create new `.md` file in `src/content/blog/`
2. Add frontmatter (title, description, date, tags)
3. Write content in Markdown
4. Build site - post automatically appears in blog index

### Modifying Styles

1. Identify the component or section to modify
2. Find corresponding CSS file in `src/styles/components/`
3. Update styles using design tokens where possible
4. Test across all breakpoints

### Adding a New Component

1. Create `.astro` file in appropriate folder
2. Define props interface
3. Create corresponding CSS file if needed
4. Import and use in pages/layouts
5. Document props and usage

---

This folder structure is designed to be:
- **Maintainable**: Clear organization and naming
- **Scalable**: Easy to add new features and content
- **Performant**: Optimized asset loading and minimal JS
- **Developer-Friendly**: Clear patterns and conventions
- **Extensible**: Room to grow without restructuring
