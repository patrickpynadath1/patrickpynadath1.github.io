$\mathcal X$: the space of finite text sequences. $P$: the reference distribution. $Q$: the generated distribution, including its decoding settings.

| $W_p(\mu,\nu)$ | Order-$p$ Wasserstein distance. |

For distributions on a Euclidean space,

$$
W_p(\mu,\nu)=
\left(
\inf_{\pi\in\Pi(\mu,\nu)}
\int \lVert u-v\rVert_2^p\,d\pi(u,v)
\right)^{1/p},
$$

where $\Pi(\mu,\nu)$ is the set of couplings with marginals $\mu$ and $\nu$.

### Information-theoretic quantities

$$
H(P)=\mathbb E_{X\sim P}[-\log_2 P(X)],
\qquad
D_{\mathrm{KL}}(P\Vert Q)
=\mathbb E_{X\sim P}\!\left[\log_2\frac{P(X)}{Q(X)}\right].
$$

Units: bits. [@shannon1948]

### Coding rates & reference savings

$$

$$
r_C^{(0)}(x)=\frac{L_C(x)}{b(x)},
\qquad
s_{C,d_D}(x)=r_C^{(0)}(x)-r_{C,d_D}(x).
$$

## Existing metrics

### Gradient Moment (GM)

| Symbol | Meaning |
| :--- | :--- |
| $R_\theta$ | Fixed pretrained evaluator. |
| $\mathcal L_\theta(x)$ | Token-averaged negative log-likelihood of $x$. |
| $g_\theta(x)$ | Gradient of $\mathcal L_\theta(x)$. |

$$
g_\theta(x)=\nabla_\theta\mathcal L_\theta(x).
$$

$$
\operatorname{GM}_\theta(P,Q)
=
\left\lVert
\mathbb E_P[g_\theta(X)]-\mathbb E_Q[g_\theta(Y)]
\right\rVert_2^2.
$$

[@franca2026]

### Energy distance

$\phi:\mathcal X\rightarrow\mathbb R^k$: feature map. $X,X'\sim P$ and $Y,Y'\sim Q$: independent samples.

$$
\begin{aligned}
\operatorname{ED}_{\phi}(P,Q)
={}&2\mathbb E\lVert\phi(X)-\phi(Y)\rVert_2\\
&-\mathbb E\lVert\phi(X)-\phi(X')\rVert_2\\
&-\mathbb E\lVert\phi(Y)-\phi(Y')\rVert_2,
\end{aligned}
$$

[@franca2026]

### Sliced Optimal Transport for Language (SOL)

| Symbol | Meaning |
| :--- | :--- |
| $h_t(x)\in\mathbb R^d$ | Contextual token state at position $t$. |
| $\mu_x$ | Empirical token-state measure for $x$. |
| $\mathsf P_h,\mathsf Q_h$ | Distributions over document token-state measures. |
| $\xi$ | Token-state projection direction. |
| $g$ | Gaussian-process draw for the second projection. |
| $M_{\xi,g}$ | Double-sliced projection of a document measure. |

$$
\mu_x=\frac{1}{T_\tau(x)}
\sum_{t=1}^{T_\tau(x)}\delta_{h_t(x)},
\qquad h_t(x)\in\mathbb R^d.
$$

$$
\operatorname{SOL}(P,Q)^2
=
d\,\mathbb E_{\xi,g}
\left[
W_2^2\!\left(
(M_{\xi,g})_\#\mathsf P_h,\,
(M_{\xi,g})_\#\mathsf Q_h
\right)
\right].
$$

[@sol2026]

### MAUVE

$\widetilde P,\widetilde Q$: quantized distributions of pretrained text embeddings. $M_\alpha$: their mixture.

$$
M_\alpha=\alpha\widetilde P+(1-\alpha)\widetilde Q,
\qquad \alpha\in(0,1),
$$

[@mauve2021]

## Our proposed compression metric

### Definition

<div className="metric-algorithm">

**Definition: compare how well real and generated text compress using the same real-data dictionary.**

$$
\text{rate}(x)=\frac{\text{compressed bits of }x\text{ using the dictionary}}{\text{UTF-8 bytes in }x}
$$

$$
\boxed{\text{score}=W_1(\text{real-text rates},\;\text{generated-text rates})}
$$

- **One rate per document:** compress each document separately with the same dictionary; reset the compressor between documents.
- **Equal weight per document:** compare the two lists of rates using one-dimensional Wasserstein distance.
- **Interpretation:** lower means the rate distributions are closer; zero does not imply the text distributions are identical.
- **Units:** bits per UTF-8 byte; no language-model evaluator required.

</div>

### Computation

<div className="metric-algorithm">

**Algorithm**

1. **Build the dictionary** from a reference-data fit split; keep the real evaluation documents separate.
2. **Compress the real evaluation documents** individually using that dictionary; record each document's bits per byte.
3. **Compress the generated documents** in exactly the same way, using the same dictionary.
4. **Compare the rate lists** with Wasserstein distance.

- **For equal-sized lists:** sort both lists, pair rates by rank, and average their absolute differences:

$$
\text{score}=\frac{1}{n}\sum_{i=1}^{n}|a_i-b_i|,
$$

- **Here:** $a_i$ and $b_i$ are the sorted real and generated rates, respectively; each list contains $n$ documents.
- **For unequal-sized lists:** use the standard one-dimensional Wasserstein calculation with equal weight per document within each list; do not truncate either list.
- **Our default:** Zstandard level 10, window log 23, a 64 KiB raw real-data dictionary, and independent compression frames.

</div>

## Experiments

### Does it track downstream performance?

- **Question:** does reference-conditioned compression distance track downstream task performance?
- **TL;DR:** Compare compression and baseline metrics with published downstream accuracy across Pythia sizes, training checkpoints and decoding settings.
- **Core results:** The association depends on decoding; use the correlation tables and within-size checks below rather than treating the pooled trend as universal.

<details className="experiment-setup">
<summary>Experimental setup, methodology & interpretation</summary>

- **Metric:** forward conditional-rate Wasserstein-1; smaller distances indicate closer coding-rate distributions.
- **Comparators:** SOL, handcrafted-feature energy distance, Gradient Moment, and Qwen3-8B-Base negative log-likelihood; all displayed scores use lower-is-better orientation.
- **Scope:** Pythia; separate analyses for each decoding setting.

#### Experimental setup

- **Model sizes:** 160M, 410M, 1B, and 6.9B.
- **Training checkpoints:** 3K, 13K, 33K, 63K, 103K, and 143K updates per size.
- **Decoding:** temperatures 0.7, 1.0, and 1.3 without truncation; temperature 1.0 with top-p 0.95; temperature 1.0 with top-k 20.
- **Generation pool:** 1,024 unconditional sequences per setting; 1,024 model-native tokens per sequence; generation seed 2026; EOS/BOS prompt excluded from evaluated text; generation continues through EOS.
- **Displayed analysis:** cached 512-sequence candidate bank split into 256 fit and 256 held-out sequences; 512 Pile reference sequences split into 256 fit and 256 held-out sequences; split seed 2026.
- **Forward score:** real-data fit dictionary only; 256 held-out real sequences versus 256 held-out generated sequences; generated fit samples are unused by this direction.
- **Downstream target:** unweighted mean accuracy across seven published five-shot evaluations: ARC-Challenge, ARC-Easy, LAMBADA, LogiQA, PIQA, SciQ, and WinoGrande; WSC and MMLU excluded from this aggregate.
- **Observation count:** 24 size–checkpoint pairs per decoding setting; 120 metric measurements overall; five decoding settings share each checkpoint's downstream target.

#### Measurement and analysis

- **Compressor:** Zstandard level 10; window log 23; fixed 64 KiB raw reference dictionary.
- **Coding protocol:** independent compression frame per sequence; adaptation within each sequence permitted; no context carried between evaluated sequences.
- **Normalization:** compressed bits per original UTF-8 byte; frame overhead included; shared dictionary transmission excluded.
- **Comparison:** exact empirical one-dimensional Wasserstein-1 between conditional coding rates; equal sequence weights; no histogram bins.
- **Association:** Spearman correlation between negative distance and downstream mean accuracy; positive correlation means lower distance accompanies higher accuracy.
- **Comparator sample counts:** SOL, energy distance, and Gradient Moment use 512 generated sequences per setting; Qwen likelihood uses 1,024; conditional compression uses 256 held-out sequences. Same 24 checkpoints, different cached sample budgets; not a sample-matched head-to-head comparison.
- **Comparator inputs:** SOL and Gradient Moment retokenize the text with a 1,024-token cap; energy distance uses the full text; sequence counts and tokenizer horizons differ from paper-default protocols.
- **Likelihood:** token-weighted Qwen3-8B-Base negative log-likelihood, expressed in bits per Pythia token; no compression penalty added.
- **Unigram entropy:** no complete saved Pythia checkpoint table found; omitted rather than replaced with compression rate or combined with likelihood using an arbitrary sum.
- **Controls:** separate pooled correlations, within-size correlations, and leave-one-size-out correlations; no fitted regression line or independence-based significance test.

### Does it detect adversarial samples?

- **Question:** do artificial samples receive worse scores than real OpenWebText, and by how much?
- **TL;DR:** Score four families of synthetic text against a real OpenWebText control.
- **Core results:** Conditional compression, SOL, energy distance, Gradient Moment and JCD place all 73/73 settings above the real control; Qwen NLL does so for 40/73. These are observed margins, not significance tests.

<details className="experiment-setup">
<summary>Experimental setup, methodology & interpretation</summary>

- **Scope:** four França-inspired sampler families; 73 parameter/seed configurations; real-data control from the same experiment suite [@franca2026].

#### Samplers

| Sampler | Construction in this experiment | Configurations |
| :--- | :--- | ---: |

- **Conditional compression:** Zstandard level 10, window log 23, fixed 64 KiB raw real-data dictionary; 256 held-out real and 256 held-out generated sequences; independent frames; equal sequence weights.

$$

$$

- **Positive margin:** the adversary receives a worse score than the real control.
- **Negative margin:** the adversary receives a better score than the real control.
- **Zero line:** equality with the observed real control; not a statistical decision threshold.
- **Dots:** individual configurations; vertical offsets separate overlapping points and have no statistical meaning.
- **Short vertical marks:** family medians; computed from unrounded scores.
- **Axes:** independent linear scales in each metric's native units; raw margin magnitudes are not comparable across metrics.

- **Control uncertainty:** one real-control configuration in this sweep; no confidence bands or significance claims.
- **Ratios:** not used; near-zero or negative real-control scores can make ratios unstable or misleading.

- **Selection criterion:** evaluate against reference data without requiring a pretrained language-model evaluator.
- **Reading this section:** distinguish observed failures, incomplete diagnostics, and methods excluded because they do not meet the model-free objective.
- **Not a claim that every earlier metric failed:** several detect every França setting; those successes alone do not establish sensitivity to structure or distributional similarity.

### The metric we decided on

- **Current main candidate:** Wasserstein distance between per-document coding rates under the same fixed real-data context.
- **Why retain it:** entirely compressor-based; references determine the context; responds to all three standalone-rate-matched attacks in the separate held-out test.
- **Why keep ablations:** standalone rates, generated-context rates and the bidirectional sum expose which parts of the score contribute.
- **Known limit:** real-context conditional W₁ decreases for all five paired structural transformations; the bidirectional sum does not fix that result.
- **Evidence:** [standalone-matched attacks](#standalone-compression-matched-adversaries), [paired structural tests](#paired-structural-tests), [downstream evaluation](#does-it-track-downstream-performance).

### The obvious baseline: likelihood minus entropy

- **Yes, the natural theoretical baseline is cross-entropy minus generated-distribution entropy:**

$$
H(Q,R)-H(Q)=D_{\mathrm{KL}}(Q\Vert R),
\qquad H(Q,R)=\mathbb E_{X\sim Q}[-\log_2 R(X)].
$$

- **Target distinction:** this is KL to the evaluator distribution $R$. It equals KL to the real-data distribution $P$ only if $R=P$.
- **Practical baseline:** replace $H(Q)$ with a Zstandard coding rate, using the same source-token denominator as the Qwen NLL:

$$
J_C(Q;R)=h_R(Q)-c(Q).
$$

- **Approximation caveat:** Zstandard's finite-sample coding rate is not the true entropy rate; Qwen is not the true reference distribution. This subtraction is a diagnostic residual, without KL's guaranteed nonnegativity or identity-of-indiscernibles.
- **Reference-centered version:** compare that residual with the measured real-control residual:

$$
\Delta J_C(Q,P;R)
=\big[h_R(Q)-c(Q)\big]-\big[h_R(P)-c(P)\big].
$$

- **Even with exact entropy:** this becomes $D_{\mathrm{KL}}(Q\Vert R)-D_{\mathrm{KL}}(P\Vert R)$, not generally $D_{\mathrm{KL}}(Q\Vert P)$.
- **If “reference number” means subtracting a fixed reference entropy:** $h_R(Q)-c(P)$ simply shifts likelihood by a constant; it has exactly the same ranking as likelihood, and is not generally KL.
- **If it means matching both real-data statistics:** the obvious alternative is the two-dimensional point $(h_R(Q),c(Q))$ relative to $(h_R(P),c(P))$, or the following equal-weight summary:

$$
A_C(Q,P;R)=|h_R(Q)-h_R(P)|+|c(Q)-c(P)|.
$$

- **Interpretation:** matches two scalar statistics; not a distributional distance. Both terms here use bits per GPT-2 source token; the unit weight is a baseline choice, not a fitted coefficient.
- **Results below:** newly derived from existing full-bank measurements. These baselines were not the evidence that originally motivated the metric choice; they are added now to make the obvious alternatives explicit.
